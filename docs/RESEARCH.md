# 研究期测评摘要

lingshu-ng 在成为企业向项目之前（2026-10-09 至 10-15，版本 v1.0–v1.30），经历了一段以检索质量为主的研究迭代。本页只保留结论；完整报告、预登记、逐题读数和测评脚本的说明存档于提交 [`00152d6`](https://github.com/Liyang1145/lingshu-ng/tree/00152d66b44007ecf8ff17203786db8a48cee222)（根目录 `REPORT_*.md`、`PREREG_*.md`，以及 `bench_*/`、`evalsuite*/` 下的报告）。测评脚本本身仍在主分支的 `bench_*/`、`evalsuite*/` 目录里。

自 v1.16 起，检索、版本链与中文指标只作回归门（每次改动须逐题持平），不再开调优轮。

## 证据分两层

**外部基准**：上游作者的 [hive-memory-bench](https://github.com/FuRongJun-1999/hive-memory-bench) 检索轨（92 题，k=10），由我们自己跑分。ng 必需章 cid 召回 .6541，上游集成修复版 .5989，BM25 基线 .6683；ng 并未超过 BM25。可选的精排档（bge-m3 + bge-reranker-base）cid 达 .7826，代价是干扰项误召回升高、每问约 5 秒（2 核 CPU）。

**自建测评**：r 系列、HARD 榜以及英文、中文、版本链三条线的保留集。题目与判分由我们设计，存在自评偏差，只能视作逐项核对上游 issue 与设计声明的记录，不能视作独立评价。

## 各线结论

| 线 | 结论 | 未胜项 |
|---|---|---|
| 英文词级召回（gen） | 在 ConvoMem、LoCoMo 等未暴露保留集上显著优于队友方案 TriCue v3 与多维 v3×3 | LongMemEval 轮级 t@10 与 TriCue 持平 |
| 中文联想通路（zh） | 可选本地重排后，DuRT 同分布保留集召回显著提升，OOD 保留集无回退 | 误用（召回不该召回的段）仍输，估计标注天花板约 .815 |
| 版本链（chain，可选，缺省关） | 零 LLM 抽取迭代到 v27；每次缺省升级的门槛是在新保留集上比上一版高 .05 | 叙事体裁完全正确率约 .37 |

## 与上游的同口径对照

见 [VS_UPSTREAM_cb3a6ea.md](VS_UPSTREAM_cb3a6ea.md)。ng 仍不如上游的项：库文件体积更大、晋升延迟更高、冷 import 有缓存时略慢。
